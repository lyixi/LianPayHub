# 管理端架构

## 职责与边界

管理端由静态控制台 `/console/` 和管理 API `/admin/**` 组成，供内部管理员维护 APP、平台配置、商品/套餐、购买页、订单、用户、设备、会员、报表和审计数据。

管理端是运营入口，不是另一套业务系统：人工开通会员、退款、修改商品等操作必须调用核心服务，和客户端请求共享同一状态机与校验规则。

## 身份与安全

- 仅 `/admin/auth/login` 允许匿名访问；其余 `/admin/**` 要求管理员 JWT。
- 生产环境启用管理员 IP 白名单、首次登录改密、强密码和操作审计。
- 后续将管理员角色与 APP 数据范围落地：超级管理员、运营、财务、客服、只读；所有查询与写入都按授权 `appId` 过滤。
- 凭据配置只显示脱敏值，导出、退款、重置密钥和修改支付配置应有独立权限与原因记录。

## 官网内容管理扩展

官网不应让开发人员通过修改前端源码维护文案。管理端将新增“官网内容”模块，管理产品展示、下载版本、Banner、公告、FAQ、联系信息、SEO 元数据及合作线索。发布内容后由官网公开 API 仅返回已发布且允许公开的版本。

内容模型与订单/支付模型分开；页面展示配置不能保存支付密钥、内部备注或用户数据。

AI 可作为内容草稿和 SEO 建议助手，但必须与现有面向用户的 AI 网关隔离，且只能产出待审核草稿，不能自动发布或执行高风险后台操作。详细约束见[官网内容运营与 AI 预留](content-and-ai.md)。
