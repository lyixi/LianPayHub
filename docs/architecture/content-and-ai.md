# 官网内容运营与 AI 预留架构

## 1. 旧站功能盘点与重构归属

经检查 `lyixi.com` 当前站点，需保留或重新评估的能力包括：首页轮播、产品中心和产品详情；软件分享、资料教程、文学投稿、视频展示等内容栏目；主播/写手案例；论坛；公司介绍与文化；在线留言；招聘与简历提交；在线客服、二维码、联系方式、备案、站点地图与多语言入口。

| 旧站能力 | 重构后的前台 | 后台能力 | 优先级 |
|---|---|---|---|
| 首页轮播、产品中心、产品详情 | 首页、产品列表/详情、下载页 | Banner、产品、版本、媒体素材、SEO | P0 |
| 软件、教程、文学、视频 | 资讯/资源列表和详情 | 栏目、文章、标签、定时发布、审核 | P1 |
| 案例 | 案例列表和详情 | 案例内容、关联产品、排序 | P1 |
| 公司与文化 | 关于我们页面 | 单页内容、联系方式、备案信息 | P0 |
| 留言/咨询 | 联系我们表单 | 线索收件箱、状态、负责人、回复记录 | P0 |
| 招聘、简历提交 | 职位页、简历投递页 | 职位、简历附件、候选人流程、访问审计 | P1 |
| 在线客服、二维码 | 悬浮入口、客服/社媒跳转 | 渠道链接与二维码素材配置 | P1 |
| 论坛 | 独立社区或第三方社区链接 | 内容审核与社区运营（若自建） | P2，单独立项 |

论坛不应作为官网首期的附带功能：账号、发帖、评论、审核、反垃圾、举报、搜索、通知和数据合规构成一个独立产品。首期保留跳转入口或接入成熟社区；只有明确有社区运营资源后再自建。

## 2. 前台设计与技术边界

当前官网作为本项目内独立静态模块交付，由 Spring Boot 提供稳定页面路由和 `/api/site/v1/**` 内容数据。它与两个管理台共享部署单元，但不共享管理员凭据、页面资源或运行时状态。后续 SEO 和内容规模需要 SSR/静态生成时，可将官网前端物理拆出，后端内容域与接口契约保持不变。

建议首期信息架构：

```text
首页
├─ 产品（列表、详情、下载/购买）
├─ 资源与动态（软件、教程、文章、视频）
├─ 案例
├─ 关于（公司、文化、联系方式、招聘）
└─ 联系/咨询
```

每个页面输出稳定 URL、title、description、Open Graph 图、canonical、sitemap 与 robots 规则；旧站 `?type=...&S_id=...` URL 通过 Nginx 或网关配置 301 重定向至新 URL，迁移前先导出旧 URL—新 URL 对照表，避免损失已有收录。

## 3. 官网内容域

当前首期已经落地 `WebsiteSiteSettings`、`WebsiteProduct`、`WebsiteArticle`、`WebsiteMedia` 和 `WebsiteLead`。首页不再把品牌文案、能力节点、公司原则或产品演示写死在前端：站点级内容由 `/admin/website/site` 维护，产品卡片与主视觉演示由 `/admin/website/products` 维护，文章由 `/admin/website/articles` 维护，图片资产由 `/admin/website/media` 维护，前台只负责版式和交互。后续导航、案例和招聘继续按下表扩展，避免重新把运营内容放回静态文件。

为避免展示内容散落在 APP、套餐或购买页表中，新增独立 `content` 模块。建议数据模型如下：

| 实体 | 用途 | 关键字段 |
|---|---|---|
| `site_setting` | 站点全局配置 | 品牌、联系方式、备案、社媒、默认 SEO |
| `navigation_item` | 菜单与页脚导航 | 标题、链接、位置、排序、状态 |
| `banner` | 首页/栏目 Banner | 标题、图片/视频、CTA、投放时间、状态 |
| `content_category` | 资讯、教程、视频等分类 | slug、父级、排序、SEO |
| `article` | 文章、教程、新闻、视频、单页 | slug、正文、封面、状态、发布时间、SEO |
| `product_profile` | 官网产品展示扩展 | 关联 `appId`、slug、卖点、截图、下载/购买 CTA |
| `download_release` | 产品版本下载 | 平台、版本、文件、更新说明、发布时间、状态 |
| `case_study` | 客户/作品案例 | 关联产品、内容、素材、排序、状态 |
| `lead` | 联系/留言线索 | 来源、姓名、联系方式、内容、处理状态、负责人 |
| `job_posting` / `job_application` | 招聘与简历 | 职位、简历文件、处理状态、最小化访问范围 |
| `website_media`（已实现） | 官网图片资产 | 存储键、URL、MIME、大小、标题、替代文本、说明 |
| `content_revision` | 可回滚版本与审核记录 | 实体、版本、变更人、差异、审核/发布时间 |

产品展示 `product_profile` 关联已有 `AppInfo`，而售卖方案继续复用 `ProductInfo` / `ProductPlan` / 支付服务。展示文案和图片不写入支付/会员表；价格和权益从服务端业务域读取或由其明确发布。

## 4. 管理后台信息架构

在现有管理台增加“官网运营”一级模块：

```text
官网运营
├─ 站点设置与导航
├─ Banner 与媒体库
├─ 产品展示与下载版本
├─ 内容中心（文章、分类、标签、案例）
├─ 联系线索
├─ 招聘与简历
├─ 发布计划、版本与回滚
└─ SEO、重定向与站点地图
```

内容状态统一为 `DRAFT → IN_REVIEW → PUBLISHED → ARCHIVED`。发布者、审核者和管理员应是不同权限；发布只产生已发布版本，前台只读已发布版本。简历、联系方式和留言属于个人信息，必须限制可见角色、下载审计、保留期限和删除流程。

## 5. 官网内容 API

在既有 `/public/**` 交易接口之外使用官网专用的 `/api/site/v1/**`；读取接口保持只读，写入仅开放受控线索提交：

- `/site`、`/navigation`、`/banners`：站点配置与导航。
- `/products`、`/products/{slug}`、`/downloads/{productSlug}`：产品与下载。
- `/categories/{slug}/articles`、`/articles/{slug}`、`/cases`：内容与案例。
- `POST /leads`、`POST /job-applications`：受验证码、限流、文件安全扫描与反垃圾保护的受控提交入口。
- `/sitemap.xml`：只输出已发布内容的规范 URL。

所有列表只返回 `PUBLISHED` 数据；静态内容使用 CDN 缓存，后台发布后精确失效缓存。公开查询严禁返回草稿、内部备注、管理员信息、支付配置或个人信息。

## 6. AI 内容运营预留（不在本阶段实现）

AI 完全可用于改写产品介绍、生成新闻初稿、提取标签/SEO、生成多版本标题和编辑图片说明。现有 `AiProviderConfig`、`AiProviderRegistry` 与供应商适配器可复用，但当前 `/api/ai/chat` 属于客户端用户能力，**不得直接用于后台内容写入**。

应新增独立的 `admin-ai` / `content-ai` 应用层：

```text
管理员操作 -> Admin AI API -> 内容 AI 编排服务 -> 现有 AI Provider Registry
                              -> AI 任务/用量/审计/草稿版本
管理员审核 -> 内容发布服务 -> 已发布内容 + CDN 缓存失效
```

预留实体：`ai_task`（输入、状态、模型、耗时、费用）、`ai_generation`（输出、引用内容、版本）、`ai_usage_ledger`（用量/预算）、`ai_prompt_template`（版本化提示词）和 `ai_action_audit`（操作者、审批者、发布结果）。AI 默认只可创建或更新草稿版本；不能自动发布、删除内容、改支付/账号/权限配置，也不能代表管理员发送外部消息。

接口应以受限动作而非任意自然语言写库，例如：`POST /admin/ai/content-drafts`、`POST /admin/ai/articles/{id}/rewrite`、`POST /admin/ai/articles/{id}/seo-suggest`。输入输出需结构化校验、敏感词/版权风险提示、限额、角色授权和完整审计；引用用户提交内容或外部网页时，视为不可信文本，不能让其改变系统指令或触发后台操作。

## 7. 实施顺序

1. 确认旧站内容盘点、保留/下线清单及 URL 重定向表。
2. 建立 `content` 数据模型、媒体存储、后台草稿—审核—发布流程和 `/api/site/v1` 内容接口。
3. 建设官网前端并先上线首页、产品、关于、联系、下载；完成 SEO、统计和 301 迁移。
4. 接入资讯、案例、招聘及线索运营；论坛单独评审。
5. 内容治理成熟后再启用 AI 草稿助手与预算/审批机制。
