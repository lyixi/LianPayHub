# 客户端 API 架构

## 服务对象

`/api/**` 面向公司自有 APP、桌面端、小程序和受控的服务端调用。已覆盖认证、设备、会员、支付、AI、搜索、云同步、用户资料、用户配置和适配上报。

详细接口清单与请求示例暂见 [现有对外接入文档](../integration-api.md)；总入口约束见 [总接口文档](../api/overview.md)。

## 鉴权分层

| 调用情境 | 身份方式 | 典型路径 |
|---|---|---|
| 用户本人操作 | 用户 JWT | `/api/user/**`、`/api/sync/**`、`/api/configs/**` |
| APP 服务端调用 | `X-App-Id` + Secret 或签名 | 设备、会员、订单及按配置受保护的接口 |
| 无用户态初始化 | 限流 + 验证码/APP 鉴权 | 登录验证码、登录、设备注册 |
| 支付平台通知 | 支付渠道签名验签 | `/api/payment/notify/{payChannel}` |

客户端不能携带管理员 JWT，也不能调用 `/admin/**`。移动端不应内置 `appSecret`；如需 APP 鉴权，应经由公司服务端签名，或使用可撤销、限权的客户端凭证方案。

## 兼容性

客户端发布后升级滞后，现有 `/api/**` 参数和响应不可随意破坏。新增可选字段优先保持兼容；语义或字段结构无法兼容时新增 `/v2/api/**`，而不是复用旧字段表达新含义。
