# 联付中枢系统总览

## 定位

联付中枢是公司的统一业务中枢：对内承载运营管理，对外为多个产品提供账号、会员、支付、设备、云同步和平台能力，并将官网展示及购买入口纳入同一产品与运营数据体系。

## 目标模块

```text
官网前端 ────────> 官网内容 API (/api/site/v1，已实现) ───┐
购买落地页 ──────> 购买 API (/public，已实现) ──┤
APP/小程序/服务 ──> 客户端 API (/api，已实现) ──┼─> 核心领域服务 ─> MySQL/Redis/第三方平台
管理后台 ────────> 管理 API (/admin，已实现) ──┘
支付渠道 ────────> 支付回调 (/api/payment/notify/**)
```

核心领域服务不是一个 HTTP 入口，而是被管理、客户端和公开模块共同调用的业务规则层。任何入口都不得绕过它直接修改订单、会员、支付或商品数据。

## 当前与目标

当前为 Spring Boot 模块化单体：`web`、`service`、`domain`、`repository`、`security` 已在一个应用内。保持单一代码库和数据库可减少当前阶段的运维复杂度。

目标不是立刻拆微服务，而是先完成路由、身份、代码和部署隔离：官网 `/`、官网运营 `/admin/`、业务控制台 `/console/`、公司程序接口 `/api/**` 与交易入口 `/public/**` 各自稳定；管理员 JWT、用户 JWT、APP 凭据/签名、支付渠道验签不能互用；入口层只编排请求，领域规则集中到 `service`。

## 物理拆分触发条件

满足任一项后，可将入口模块独立部署：官网流量需要单独扩缩容；后台需要网络隔离；官网由独立团队持续发布；或合作伙伴 API 需要独立 SLA 与限额。在此之前，不建议复制会员、订单、支付等表或在两个后端分别实现相同规则。
