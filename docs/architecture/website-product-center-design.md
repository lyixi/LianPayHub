# 公司官网与产品中心设计

## 1. 产品定位

网站仍然是懒一夕的正式公司官网，不是独立应用商店。它同时承担三项任务：

1. 建立公司品牌与技术可信度。
2. 让访客快速发现、理解并下载合适的产品。
3. 持续发布公司新闻、产品动态和服务信息。

产品是公司的核心业务，因此拥有比普通企业官网更完整的产品中心，但首页不能被版本号、安装包和评论列表占满。首页负责“认识公司和产品”，产品详情页负责“判断是否适合并完成下载”，后台负责“安全、高效地持续运营”。

## 2. 全站信息架构

```text
公司官网 /
├─ 品牌首屏：公司主张、重点产品现场、主要行动
├─ 产品矩阵：重点产品 + 全部产品入口
├─ 公司能力：设计、工程、长期维护能力
├─ 公司数据：成立时间、用户规模、产品数量、服务稳定性
├─ 新闻动态：公司新闻、产品更新、技术文章
├─ 关于公司：使命、团队与联系方式摘要
└─ 页脚：产品、公司、资源、法律与备案

产品中心 /product
├─ 全部产品
├─ 分类与平台筛选
└─ 产品卡片：图标、名称、定位、平台、当前版本、主要行动

产品详情 /product/{slug}
├─ 产品身份与下载
├─ 截图/视频
├─ 产品介绍与核心能力
├─ 当前版本及各平台安装包
├─ 更新历史
├─ 用户评分与精选评论
├─ 建议反馈
├─ 帮助与常见问题
└─ 相关产品

新闻 /news
├─ 公司新闻
├─ 产品动态
└─ 技术与观点

关于 /about
联系 /contact
官网运营后台 /admin
```

导航保持企业官网语义：`产品 / 动态 / 关于 / 联系`。下载是产品详情页的主行动，不在公司首页导航中堆叠平台下载入口。

## 3. 首页设计

### 3.1 页面叙事

首页按“品牌认知 → 产品证明 → 公司可信度 → 持续经营 → 联系转化”展开：

```text
┌─────────────────────────────────────────────────────────┐
│ Logo       产品   动态   关于   联系        主题 / 探索产品 │
├─────────────────────────────────────────────────────────┤
│ 公司价值主张（左）         重点产品真实界面（右）          │
│ 简洁说明 + 探索产品                                     │
├─────────────────────────────────────────────────────────┤
│ 产品矩阵：1 个重点产品 + 数量不固定的产品列表              │
├─────────────────────────────────────────────────────────┤
│ 我们如何做产品：设计判断 / 工程质量 / 长期维护              │
├─────────────────────────────────────────────────────────┤
│ 公司事实与数据，不使用虚假客户 Logo                         │
├─────────────────────────────────────────────────────────┤
│ 最新动态 3 条                         查看全部动态          │
├─────────────────────────────────────────────────────────┤
│ 关于公司摘要 + 联系方式                                  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 产品区

- 后台发布多少产品，首页就能展示多少，不依赖“前四个”固定槽位。
- 后台可指定一个重点产品；未指定时使用排序第一的已发布产品。
- 重点产品展示真实截图、名称、短说明和“查看产品”。
- 其他产品采用两列目录卡，展示图标、名称、定位、支持平台和当前稳定版本。
- 产品较多时首页默认显示前 6 个，并提供“查看全部产品”，而不是无限拉长首页。
- 产品卡片不展示完整评论、更新日志或所有安装包，避免首页退化成商店货架。

### 3.3 公司内容

“公司能力”不是空泛的三张特性卡，而是对外可验证的工作原则，例如：

- 产品设计：从实际工作流中删减步骤，而非堆叠功能。
- 工程交付：多平台发布、自动更新、稳定接口和故障恢复。
- 长期维护：持续版本更新、兼容旧数据、公开记录重要变化。

新闻区只展示最近 3 条已发布内容。公司新闻、产品版本和技术文章使用同一内容系统，但具有不同分类和视觉标记。

## 4. 产品目录页

产品数量增长后，首页不应承担全部浏览任务。`/product` 提供正式产品目录：

- 顶部不是营销 Hero，而是一句清楚的目录说明与产品搜索。
- 筛选项来自后台：产品类别、支持平台、免费/付费、正式/测试阶段。
- 排序支持推荐顺序、最近更新；不提供无意义的复杂排序。
- 卡片显示产品图标、名称、定位、平台图标、当前版本与更新时间。
- 产品处于内测、停止维护或即将发布时，显示明确状态，不伪装成可下载。
- 搜索和筛选在 URL 中保存，返回页面时保留用户选择。

## 5. 产品详情页

详情页借鉴应用商店的信息效率，但保持公司官网现有的液态玻璃、环境光和编辑式排版，不复制 App Store 的白色列表界面。

### 5.1 首屏

```text
┌─────────────────────────────────────────────────────────┐
│ ← 全部产品                                             │
│ [应用图标]  产品名称                   [获取 / 下载 ▾]    │
│             一句话定位                   Windows 版本信息 │
│             评分 · 当前版本 · 最近更新 · 支持平台         │
├─────────────────────────────────────────────────────────┤
│             横向截图 / 视频媒体轨道                       │
└─────────────────────────────────────────────────────────┘
```

- 应用图标是首屏的重要品牌资产，不能再使用产品名称首字占位。
- 主按钮自动推荐当前设备的平台安装包，但必须允许用户展开选择其他平台。
- 下载前明确显示平台、架构、版本、文件大小和发布时间。
- 外部商店下载使用对应商店名称，如“前往 Microsoft Store”，不伪装成本地下载。
- 没有可用安装包时，主按钮改为“申请内测”“查看购买方式”或“即将发布”。

### 5.2 媒体展示

- 支持图片和视频，按后台排序展示。
- 每项包含标题、说明、替代文本、媒体类型和可选设备外框。
- 桌面端为横向沉浸轨道；移动端为可吸附滑动列表。
- 点击进入灯箱，支持键盘方向键、ESC 和触摸滑动。
- 首屏最多预加载第一张图，其他媒体懒加载，低性能设备禁用视差与重模糊。

当前实现采用 `WebsiteProduct.mediaJson` 作为过渡性的产品资产清单：后台资产必须先上传到媒体库，再通过媒体选择器绑定到产品，保存 `mediaId/url/title/altText/sortOrder`，前台详情页以缩略图轨道和主图轮播展示。后续版本可将该 JSON 平滑迁移到下方规划的 `WebsiteProductMedia` 关系表，不改变后台和前台的使用方式。

### 5.3 产品介绍

不再使用“功能标题一、内容一”。正文采用可排序内容区块：

| 区块类型 | 用途 |
|---|---|
| 富文本 | 产品故事、设计原则、长说明 |
| 图文 | 一项能力与对应界面，可左右切换 |
| 媒体 | 单张大图、视频或多图轨道 |
| 数据 | 有真实依据的性能或规模数据 |
| 引用 | 审核后的用户评价或媒体引用 |
| FAQ | 安装、兼容性、价格和隐私问题 |
| 行动 | 下载、购买、申请内测或联系支持 |

后台通过区块编辑器新增、排序、隐藏和预览内容。产品详情页因此可以适配不同产品，而不需要给每个产品写死三项功能。

### 5.4 版本和安装包

“版本”与“安装包”必须分离：一个版本可以包含多个平台和架构的安装包。

版本包含：

- 版本号、版本名称、发布渠道（稳定版/测试版/内测版）。
- 发布时间、更新摘要、完整更新内容。
- 最低系统要求、是否强制升级、发布状态。
- 多个安装包及其下载状态。

安装包包含：

- 平台：Windows、macOS、Linux、Android、iOS、Web 或其他。
- 架构：x64、ARM64、Universal 等。
- 安装形式：EXE、MSI、DMG、PKG、AppImage、商店链接等。
- 文件地址、文件大小、SHA-256、签名状态、最低系统版本。
- 下载方式：本地文件、对象存储、第三方商店、购买后下载。
- 是否为该平台默认包、是否启用、下载计数。

前台默认只展示最新稳定版本；“查看更新历史”打开完整时间线。测试版必须显著标明风险，不能与稳定版混排。

### 5.5 评分、评论和建议

三个概念分开处理：

- **评分**：1–5 星，可匿名提交，展示平均分和有效评分数。
- **评论**：用户选择公开表达的使用体验，审核后展示。
- **建议/问题**：面向产品团队的私密反馈，默认不公开。

匿名不等于无约束。系统使用匿名访客令牌、IP/UA 的短期不可逆摘要和速率限制控制重复提交；不保存明文指纹。异常频率触发验证码。用户可以在同一浏览器修改自己的评分，统计采用最后一次有效评分。

评论流程为 `待审核 → 已通过 / 已拒绝 / 垃圾信息`。前台只展示审核通过的评论，并明确“精选评价”而非暗示全部评价。管理员不能静默修改用户原文，只能隐藏、回复或标注；确需脱敏时保留审计记录。

建议表单包括：类型、内容、可选联系方式、当前版本、平台和可选附件。联系方式仅后台可见，和公开评论完全隔离。

## 6. 视觉与交互

### 6.1 延续现有风格

- 延续冷色环境光、圆角玻璃、紫青强调色与大字号排版。
- 玻璃只用于首屏下载面板、媒体焦点、筛选浮层和弹窗，不给每段正文套灰色卡片。
- 产品图标、截图和版本信息提供真实视觉内容，减少抽象占位界面。
- 应用商店式信息使用精密网格和等宽版本标签，公司的表达仍使用大标题和充分留白。

标志性视觉是 **Release Lens（版本透镜）**：产品首屏下载面板是一块高质量液态玻璃，透过它看到当前产品主视觉；切换平台时透镜中的系统信息、安装包和环境色一起平滑变化。全页只保留这一处强玻璃互动，其余区域克制，避免性能和视觉噪声。

### 6.2 反馈状态

- 下载：按下反馈、准备下载、已开始、失败重试四种状态。
- 媒体：加载骨架、失败占位、灯箱计数和键盘焦点。
- 评分：悬停预览、已选择、提交中、成功、限流提示。
- 评论：字数、是否公开、审核说明、提交成功后的状态预期。
- 空状态：没有安装包时说明原因和下一步；没有评论时邀请首条真实评价。

### 6.3 性能预算

- 产品首屏 LCP 图片提供 WebP/AVIF 多尺寸，桌面建议不超过 300 KB。
- 首屏不自动播放视频；视频只加载封面和元数据。
- 每屏真实折射玻璃不超过 2 个，低性能模式改为轻透明表面。
- 产品媒体使用懒加载和明确宽高，避免布局跳动。
- 自定义鼠标不承载功能，检测到低性能或掉帧时自动关闭。

## 7. 后台产品管理

### 7.1 产品列表

列表展示：图标、产品名、产品状态、当前稳定版本、平台、最近发布、评分、更新时间。顶部支持搜索、状态/平台筛选和新建产品；拖拽仅调整官网推荐顺序。

产品状态建议使用：

- `DRAFT`：仅后台可见。
- `PUBLISHED`：官网公开。
- `BETA`：公开但明确标记测试。
- `COMING_SOON`：可展示，不可下载。
- `ARCHIVED`：保留历史页面和下载说明，不出现在默认目录。

### 7.2 编辑器结构

不再将所有字段塞进一个长弹窗。产品编辑使用独立页面 `/admin/products/{id}`，顶部固定产品身份、保存状态、预览和发布操作，主体使用标签页：

```text
概览       名称、slug、图标、定位、类别、状态、支持与购买链接
展示内容   产品内容区块、FAQ、相关产品、SEO
媒体       截图、视频、封面、排序、替代文本
版本发布   版本时间线、更新内容、灰度/稳定状态
安装包     平台、架构、文件、校验值、系统要求、启停
评价反馈   评分概览、评论审核、官方回复、建议工单
数据       页面访问、下载、平台分布、转化和失败率
```

新建产品可以使用三步引导：基本信息 → 图标和首张截图 → 首个版本/行动方式。创建后进入完整编辑页。

### 7.3 版本发布流程

1. 创建版本草稿并填写更新内容。
2. 上传或关联各平台安装包。
3. 服务端计算文件大小和 SHA-256；运营不能手填校验结果。
4. 校验必填信息、文件可访问性、版本号重复和签名状态。
5. 预览产品页和下载选择器。
6. 立即发布或定时发布。
7. 发布后生成不可变版本记录；修订说明需保留历史。

删除已发布版本属于高风险操作，应改为下架。若安装包存在安全问题，可立即禁用单个包并展示原因，不必下架整个产品。

### 7.4 评价后台

- 顶部显示评分分布、近期趋势、待审核数和高频反馈主题。
- 评论审核支持查看上下文、通过、拒绝、标记垃圾信息和官方回复。
- 建议进入轻量工单状态：新建议、处理中、已计划、已完成、关闭。
- 联系方式默认遮罩，只有具备反馈权限的管理员可以查看。
- 批量操作必须二次确认并写入管理员操作日志。

## 8. 数据模型

当前 `WebsiteProduct` 保留产品身份字段，但应移除 `previewChapter*` 这类页面槽位式字段。建议新增以下实体：

| 实体 | 关键字段 |
|---|---|
| `WebsiteProduct` | slug、name、tagline、summary、icon、cover、category、status、sortOrder、支持/购买信息 |
| `WebsiteProductSection` | productId、type、contentJson、sortOrder、visible |
| `WebsiteProductMedia` | productId、type、url、posterUrl、title、altText、deviceFrame、sortOrder |
| `WebsiteProductRelease` | productId、version、channel、title、summary、notes、publishedAt、status |
| `WebsiteProductArtifact` | releaseId、platform、architecture、packageType、url、size、sha256、minOs、enabled、primary |
| `WebsiteProductRating` | productId、visitorTokenHash、score、status、createdAt、updatedAt |
| `WebsiteProductReview` | productId、ratingId、nickname、content、status、officialReply、reviewedAt |
| `WebsiteProductFeedback` | productId、releaseId、type、content、contact、platform、status、createdAt |
| `WebsiteDownloadEvent` | productId、releaseId、artifactId、result、referrer、createdAt |

内容区块的结构允许使用 JSON，但版本、安装包、评分和评论必须采用独立关系表，不能混在产品 JSON 中，否则无法安全统计、审核和更新单个平台文件。

评分聚合值可以缓存到产品统计表，但真实评分记录仍是事实来源。公开 API 不返回访客摘要、联系方式、审核信息或内部备注。

## 9. API 边界

### 9.1 官网读取

```text
GET  /api/site/v1/products
GET  /api/site/v1/products/{slug}
GET  /api/site/v1/products/{slug}/releases
GET  /api/site/v1/products/{slug}/reviews
POST /api/site/v1/products/{slug}/ratings
POST /api/site/v1/products/{slug}/reviews
POST /api/site/v1/products/{slug}/feedback
POST /api/site/v1/downloads/{artifactId}/resolve
```

下载使用 `resolve` 而不是直接在列表暴露所有内部存储地址，以便校验包状态、记录结果、生成短期对象存储链接和处理购买权限。公开读取接口可缓存；评分、评论、反馈和下载解析禁止 CDN 缓存。

### 9.2 后台管理

后台 API 按资源拆分产品、内容区块、媒体、版本、安装包、评价和反馈。发布版本、下架安装包、批量审核等命令使用独立动作接口，不能靠整份产品对象覆盖。

所有写操作记录管理员、变更前后摘要、请求 ID 和时间。AI 将来只能协助生成产品介绍、更新摘要、FAQ 和回复草稿，不能上传安装包、修改校验值、直接发布版本或自动通过评论。

## 10. 实施顺序

### 第一阶段：产品资料与展示

- 新数据表及兼容迁移。
- 首页产品区改读新产品摘要。
- `/product` 产品目录。
- 新产品详情首屏、媒体、内容区块和当前版本。
- 后台产品独立编辑页、媒体和内容区块。

### 第二阶段：版本与下载

- 版本、安装包、校验和平台选择器。
- 下载解析、计数、失败监控与历史版本。
- 发布校验、定时发布和安装包紧急停用。

### 第三阶段：评价与反馈

- 匿名评分、评论审核、官方回复。
- 私密建议和后台工单状态。
- 限流、验证码、隐私说明和管理员审计。

### 第四阶段：运营增强

- 产品数据看板、下载转化、平台分布。
- 相关产品推荐和新闻关联。
- AI 草稿助手，但保持人工审核与发布边界。

每一阶段都保持旧产品接口可读；先扩展数据结构并完成迁移，再切换前台读取，最后移除 `previewChapter*` 旧字段，避免一次性破坏现有官网。
