# 懒一夕官网重构：产品、UI 与发布设计

## 1. 设计结论

新官网不是旧 CMS 的换皮，也不是把后台能力直接展示到前台。它的单一任务是：让正在寻找创作、直播或效率工具的人，在一分钟内理解产品价值、找到适合自己的产品，并完成下载、购买或咨询。

目标用户包括创作者、主播、文字工作者、效率工具使用者，以及寻求合作的机构。产品矩阵是官网的主角；公司介绍、资讯和招聘为信任与转化服务。

## 2. 视觉方向：精密创作系统

选择“精密创作系统”而不是通用科技大屏：页面以真实的软件工作台作为首屏主视觉，展示灵感、章节、资料和智能能力如何进入同一条工作流。其余区域保持清晰、安静、有秩序，避免旧站的大幅轮播、装饰性背景和密集悬浮控件。

### 设计令牌

| 名称 | 色值 | 用途 |
|---|---:|---|
| 纸白 | `#F2F4F3` | 页面背景与大面积留白 |
| 墨黑 | `#101614` | 标题、按钮与深色系统区 |
| 工程蓝 | `#1859F4` | 产品链接、交互反馈与内容后台主行动 |
| 信号绿 | `#C7FF3D` | 品牌标记和极少量关键状态 |
| 数据青 | `#57D8DB` | 产品界面中的辅助状态 |
| 系统深色 | `#111A22` | 产品工作台、控制台和页脚 |

- 标题与正文：`Noto Sans SC`，通过强字重、紧凑排版和尺度对比形成品牌感；英文数字使用 `IBM Plex Mono`。
- 正文：`Noto Sans SC`，保证跨平台清晰和长文可读。
- 数据/版本号：`IBM Plex Mono`，只用于下载版本、发布时间、标签等工具性信息。
- 栅格：桌面 12 列、最大内容宽度 1240px；移动端 4 列。工具面板采用 0–6px 小圆角，不把所有区域做成“胶囊”。

### 标志性互动

首页首屏使用“写作天下”真实产品工作台：项目轨道、章节列表、编辑器与创作助理同时可见，直接证明产品和工程能力，而不是用抽象光效暗示技术。编辑光标是唯一持续动效，首屏之外只使用一次性滚动显现。

这是全站唯一强记忆动效。其他动效保持克制：页面进入时分层淡入，产品卡片悬停仅有轻微上浮和媒体裁切变化，滚动时只做一次性内容显现。遵从 `prefers-reduced-motion`，并不以动画承载关键信息。

## 3. 前台信息架构

```text
首页
产品
├─ 产品列表（按“写作 / 直播 / 效率”等任务筛选）
└─ 产品详情（价值、截图/演示、适用人群、版本、下载/购买、帮助）
资源与动态
├─ 软件与工具
├─ 教程与文章
├─ 视频
└─ 公告
案例
关于我们
├─ 公司与文化
└─ 加入我们
联系与合作
```

论坛不放入首期主导航；如要保留，放在“资源与动态”或页脚的“社区”入口，先跳转既有平台。这样不会让一个未完成的社区能力干扰用户下载产品的主路径。

### 首页结构

```text
[简洁导航：产品 / 资源 / 案例 / 关于 / 联系]                       [登录/下载]
[首屏：一句明确主张 + 创作信号带 + 两个行动：探索产品 / 查看下载]
[任务导向产品矩阵：按使用目标，而非旧 CMS 栏目]
[一个真实产品深潜：界面片段 + 解决的问题 + 去详情]
[近期动态：最多 3 条，保持新鲜而非堆新闻]
[案例/用户作品：可验证成果]
[联系、招聘、社媒/客服、备案]
```

首屏文案应直接说清业务，例如“让创作和效率工具，替你完成重复劳动”，而不是“懒到极致是生产力”这类无法解释产品的口号。每页只保留一个主行动：产品页为“下载/购买”，文章页为“查看相关产品”，招聘页为“投递简历”。

### 产品详情页

产品详情是转化页，不是图文档案。顺序为：一句用途说明、适用人群、可见的产品界面/演示、三项具体能力、版本和平台下载、价格/购买（如有）、教程与常见问题、相关产品。下载按钮必须显示平台、版本、文件大小和更新时间；收费产品须在付款前展示权益、价格、退款/客服入口。

## 4. 管理后台设计

在现有后台增加独立“官网运营”一级菜单，不与支付、用户、平台配置混排：

```text
官网运营
├─ 工作台：待审核、待发布、失败下载、未处理线索
├─ 内容：文章、分类、标签、案例、单页
├─ 产品展示：产品页、下载版本、关联购买页
├─ 首页与导航：Banner、导航、页脚、站点设置
├─ 媒体库：图片、视频、文件、使用位置和版权信息
├─ 线索与招聘：咨询、简历、处理记录
├─ 发布中心：预览、定时发布、版本、回滚
└─ SEO 与迁移：Meta、重定向、sitemap、死链检查
```

当前内容编辑采用一个“发布”按钮，提交后立即上线，不设置保存草稿、预览或审核步骤；保留撤回操作。上方发布中心及后续版本管理属于远期规划，不作为当前发布前置条件。产品展示信息关联现有 `AppInfo`；价格、权益、订单和支付配置仍归业务管理，不在内容编辑器复制一份。

权限至少拆分为：内容编辑（只能编辑草稿）、审核发布（可发布/回滚）、招聘/线索专员（只看必要个人信息）、产品运营（管理下载与展示）、管理员（配置与权限）。

## 5. AI 内容助手预留

当前 AI 平台能力可作为供应商底座复用；新增后台 AI 时提供“生成草稿”“改写”“提取 SEO”“生成摘要/标签”“为同一产品生成多渠道文案”等明确动作，而不是一个可以任意修改后台的聊天框。

每次 AI 输出都落为一个新草稿版本，并显示来源材料、模型、提示词版本、预计/实际用量。编辑者可以采纳局部内容，发布者必须人工审核。AI 无权直接发布、删除、改支付配置、访问简历全文或向外部联系人发送消息。

## 6. 生产部署与无感更新

### 推荐部署拓扑

```text
浏览器
  ├─ CDN / 对象存储：官网静态站（www.lyixi.com）
  └─ Nginx / 网关
       ├─ 官网内容 API（www.lyixi.com/api/site/v1 -> Spring Boot）
       ├─ 客户端 API（api.lyixi.com -> Spring Boot）
       └─ 管理后台（admin.lyixi.com -> Spring Boot + 管理台静态资源）
Spring Boot -> MySQL、Redis、对象存储、支付/AI/短信等外部服务
```

官网前端与后端分开发布。官网构建产物使用内容哈希文件名，上传到以版本号命名的不可变目录；完成上传和校验后，原子切换 CDN 的入口 HTML/发布清单。老资源至少保留 7–30 天，因此打开旧页面的用户仍能加载它依赖的 JS/CSS。发布/回滚只切换入口版本，无需停服务。

### 后端发布流程

1. CI 执行单元/集成测试，构建不可变镜像或 JAR，并生成版本号。
2. 先执行可回滚的数据库备份；数据库变更采取“扩展—迁移—收缩”：先加表/可空字段/索引，再发布兼容新旧代码的应用，数据迁移完成后才移除旧字段。
3. 启动绿色实例（或新滚动实例），以 `/actuator/health` 通过、数据库连接和关键依赖就绪为切流条件。
4. Nginx/API 网关将新请求逐步切到绿色实例；旧实例停止接收新请求并等待在途支付回调/请求完成。
5. 保留旧版本一段观察期；若异常立即切回旧实例。数据库收缩操作不与应用切换在同一次发布执行。

单服务器初期可用 Docker Compose + Nginx 管理蓝/绿两个应用容器；多服务器时改为负载均衡下的滚动发布或 Kubernetes。无论采用何种运行环境，配置和密钥应从环境变量/密钥服务注入，不能打进镜像或提交仓库。可执行的验收与回滚步骤见[生产发布与无感更新运行手册](../deployment-runbook.md)。

### 降低频繁更新影响的规则

- 前端：小改动按静态站原子发布；接口使用向后兼容的新增字段，旧前端可继续运行。
- 后端：使用功能开关。代码可先上线，内容域/新入口/AI 功能只对指定管理员或少量流量启用。
- 内容：草稿、审核、定时发布与 CDN 精确失效分离，改一篇新闻不需要重发整个后端。
- 高风险路径：支付、登录、会员状态变更发布时采用灰度、监控错误率与支付成功率；避免与大数据库迁移同一窗口发布。
- 可观测性：每次响应和日志携带发布版本与请求 ID；监控健康检查、接口错误率、响应时间、下载失败率、下单/支付漏斗，并为回滚保留告警阈值。

## 7. 建设阶段

| 阶段 | 交付 | 不做什么 |
|---|---|---|
| A：基础 | 视觉系统、内容模型、媒体存储、官网运营后台骨架、`/api/site/v1` | 不重做论坛，不上 AI 自动化 |
| B：首发 | 首页、产品详情、下载/购买、关于、联系、SEO | 按全新站点发布，不配置旧 URL 301 |
| C：运营 | 文章/案例、招聘、线索工作流、发布/回滚、数据看板 | 不让内容编辑直改生产数据 |
| D：增强 | AI 草稿助手、灰度/功能开关、内容实验 | 不允许 AI 自动发布 |

首发前必须完成：旧内容资产盘点、必须保留页面清单、URL 映射、下载文件校验、ICP备案/隐私/用户协议核对、统计埋点和回滚演练。
