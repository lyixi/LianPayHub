# 生产发布与无感更新运行手册

本文档定义联付中枢及官网上线的最低生产标准。它是运行手册，不替代云厂商、域名、证书和密钥的具体审批流程。

## 1. 上线前的硬性条件

- 生产使用独立 MySQL、Redis（集群部署时验证码、nonce、限流必须从本地内存迁移至 Redis）和对象存储；不可使用开发机目录或 H2。
- 生产以 `prod` profile 启动。当前该 profile 已启用 Flyway 和 `ddl-auto=validate`，数据库结构只通过 `src/main/resources/db/migration/` 的版本化迁移变更。
- 所有数据库、JWT、支付、AI、短信、邮件和对象存储凭据由部署平台环境变量或密钥服务注入。仓库 `application.yml` 的本地示例值不得作为生产值使用。
- 生产必须设置随机且足够长的 JWT secret；关闭 `payment.dev-tools-enabled`、短信调试码；开启客户端 API 签名鉴权；限制 CORS 与后台 IP 白名单。
- 备份数据库并验证可以恢复；支付回调域名、HTTPS 证书、健康检查和日志采集均已验证。

## 2. 推荐域名和网络边界

| 域名 | 服务 | 外网规则 |
|---|---|---|
| `www.lyixi.com` | 官网静态站/CDN | 仅 80/443，由 CDN 回源或静态托管 |
| `api.lyixi.com` | 客户端 API 与支付回调 | 仅 443；支付渠道回调可达 |
| `admin.lyixi.com` | 管理台和 `/admin/**` | 443 + IP 白名单/VPN，禁止通用公开访问 |
| `www.lyixi.com` | 官网内容 API `/api/site/v1/**` | 仅官网页面调用；读取可由网关/CDN 缓存，线索提交限流 |

MySQL、Redis、对象存储管理端和应用健康端口不得直接暴露公网。Nginx/API 网关负责 TLS、域名路由、请求大小限制、速率限制、访问日志和安全响应头；Spring Boot 实例仅监听私网端口。

## 3. 发布单元

| 单元 | 发布方式 | 回滚方式 |
|---|---|---|
| 官网前端 | 版本化静态构建产物上传 CDN/对象存储 | 切回上一份入口清单 |
| Spring Boot API | 不可变 Docker 镜像或带版本号 JAR，蓝绿/滚动部署 | 网关切回健康的上一版本 |
| 数据库 | Flyway 迁移 | 通过兼容代码回滚；不可逆数据操作需单独恢复方案 |
| 内容 | 草稿/审核/定时发布 | 内容版本回滚 + CDN 精确失效 |

官网构建文件必须使用内容哈希命名，且每次发布保存到独立版本目录（如 `releases/20260917-1/`）。入口 HTML 或发布清单最后原子切换；上一版静态文件保留至少 7 天，推荐 30 天，避免用户打开旧页面时资源 404。

## 4. 后端无感发布流程

1. CI 拉取固定提交，执行测试、构建产物并记录 Git SHA、构建时间和依赖版本。
2. 审阅数据库迁移。采用“扩展 → 迁移 → 收缩”：先新增表、索引或可空字段；发布能读写新旧结构的代码；异步回填数据；观察后在后续独立发布中移除旧字段。禁止同一次发布删除仍被旧实例读取的列。
3. 发布前创建可恢复的数据库备份，并验证应用配置、密钥、支付回调地址和镜像签名。
4. 启动绿色实例，等待 `/actuator/health` 正常；执行登录、会员查询、下单模拟和官网内容接口的冒烟检查。
5. 网关先将少量或内部流量转至绿色实例，观察错误率、P95 响应时间、支付成功率和日志异常；稳定后切换全部新请求。
6. 蓝色实例停止接收新请求，保留一段时间以完成在途请求。支付回调路径不应在切换中返回 5xx。
7. 观察期内保留旧镜像、上一版官网入口和数据库备份；失败时先将网关流量切回，而非仓促修改生产数据。

单台服务器可通过 Nginx 管理两个不同端口的应用容器实现蓝绿切换；多台服务器由负载均衡器/Kubernetes 进行滚动或金丝雀发布。先用单机蓝绿建立可回滚流程，比直接上复杂集群更适合当前阶段。

## 5. 前端和内容发布流程

1. 内容编辑保存草稿，在预览域名或带签名的预览链接确认桌面端、移动端、SEO 元数据和下载链接。
2. 审核者发布内容；发布服务创建内容版本并只失效相关产品页、文章页和 sitemap 缓存。
3. 官网构建或增量再生成成功后，上传完整版本资产，校验关键 URL，再切换 CDN 入口。
4. 若内容或 UI 异常，分别回滚内容版本或官网入口版本；无需回滚 API 服务。

这使日常新闻、Banner、下载链接等更新与后端代码发布脱钩，用户无需感知服务重启。

## 6. 发布验收与监控

每次发布至少检查：

- `https://api.lyixi.com/actuator/health` 可用，且不泄露敏感详情。
- 官网首页、产品详情、下载、购买页、后台登录和支付回调路径返回正确状态。
- 新旧版本客户端都可完成登录、会员查询和关键业务操作。
- Flyway schema history 无失败迁移，错误日志无认证、数据库或第三方供应商异常。
- 监控包含可用性、错误率、P95/P99、JVM/数据库连接、支付下单和回调成功率、下载失败率；告警链接到当前发布版本与请求 ID。

## 7. 频繁迭代的控制措施

- 使用功能开关：代码先上线，只向内部管理员、指定 APP 或少量用户启用新功能。
- API 只做向后兼容的字段新增；破坏性改动使用新版本路径并保留迁移期。
- 在支付、登录、会员等高风险路径采用灰度发布；大规模数据迁移与功能上线拆开。
- 每次发布都具备明确的“停止条件”和回滚负责人；AI 内容功能上线前单独进行权限和越权测试。
